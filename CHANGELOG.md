# Changelog

## 0.49.0 — unreleased

The gap-audit release. Every place where Rivet knew it was wrong and wrote it up in the docs instead of fixing it, it now either gets right or refuses. That means a lot of former warnings now stop generation, so expect `dotnet-rivet` to fail on contracts it used to wave through. Each error names the thing and says what to do instead. It comes in three parts: wrong specs that used to ship silently, promises nothing checked, and the binding, security and corpus work that finishes the job.

### Part 1: wrong specs no longer ship silently

#### Breaking

- CLI: a `[JsonConverter]` Rivet can't model is refused with `RIV1111`. That's one on a walked type (other than `[RivetScalar]` and `[RivetUnion]`), or one on a property or field. The spec used to describe the CLR shape while the converter wrote something else entirely. On a primitive-typed property, `[RivetSchemaType("string")]` pins the wire and is accepted. An enum converter belongs on the enum type.
- CLI: `[JsonNumberHandling]` with `WriteAsString` or `AllowNamedFloatingPointLiterals` on a number, from the property or from the type being serialized, is refused with `RIV1112`. That covers `Int128`, `UInt128` and `Half`, and a generic type's `T` members, since the open type is one schema for every instantiation. It puts strings on the wire where the spec says number. `AllowReadingFromString` alone is fine: numbers are still written as numbers, and the host just reads a little more generously.
- CLI: two types that share a simple name now stop generation with `RIV1007`, naming both. That covers different namespaces, nested types with the same name, and `Result` beside `Result<T>`. Before, the second one walked was quietly emitted as `Item2`, so a schema name depended on discovery order. Rename one of them.
- CLI: `BigInteger` is refused with `RIV1010`. System.Text.Json has no converter for it: it writes the struct's `IsZero`/`Sign` properties and can't read them back. Use a string of digits, or `long` or `decimal`.
- CLI: a `[JsonDerivedType]` with an int tag or no tag is refused with `RIV1014`. The base used to fall back to flattening, which describes a payload System.Text.Json never writes.
- CLI: a `[RivetUnion]` with no variant properties is refused with `RIV1018` instead of being flattened.
- CLI: a contract endpoint field that isn't `static readonly` stops generation with `RIV1001`. Rivet reads the initializer, so a field that can be reassigned, or exists once per instance, could serve something different from the spec. Declare it `public static readonly`.
- CLI: a contract endpoint field Rivet can't read stops generation with the new `RIV1113`: no initializer, an initializer that isn't a `Define.*` chain (a helper call, another field), an endpoint declared as a property, a call that isn't a Rivet builder method, an example with nothing in it, a `null` route, or any string, int or bool argument that isn't a compile-time constant. Each refusal says how to fix that case. Rivet used to skip such a field, so the operation vanished from the spec without a word. A variable passed to a builder call fared no better: `.Summary(text)` was skipped, `.Status(code)` fell back to the default status, `.ProducesFile(type)` to `application/octet-stream`, `.QueryAuth(name)` to `token`, and `.Secure(scheme)` dropped the endpoint's security. The "not a Rivet builder method" refusal had no ID before; it's `RIV1113` too.
- CLI: a response example for a status the endpoint never declares stops generation (`RIV1002` for contracts, `RIV1004` for controllers). The spec had nowhere to put the example, so it used to vanish with a warning. Declare the status, or fix the example. A status declared only by `.ResponseContent(...)` counts, for examples and headers alike.
- CLI: `.WithResponseHeader()` on a status the contract doesn't declare stops generation with `RIV1017`, rather than leaving out a header your handler sends.
- CLI: a dictionary, collection or scalar input on GET, DELETE or `.AcceptsBinary()` stops generation with `RIV1020`. It used to drop the input and carry on as if the endpoint took nothing. Use a record with one property per route or query parameter, or move the values into a JSON body.
- CLI: two `[ProducesResponseType]` on the same status fail generation with `RIV2010`. Rivet used to keep the first and drop the other's body.
- CLI: malformed `--from` contract JSON is refused (exit 1) instead of quietly degraded: a generic with no template (`RIV2007`), one brand declared two ways (`RIV2008`), a repeated response status (`RIV2010`), an unbound type parameter (`RIV2006`), a `$ref` to a type the contract never ships (`RIV2005`), a name declared twice across types and enums, and an enum without exactly one of `values`/`intValues`. The last two used to crash or let the last one win.
- CLI: an unmapped C# type, or an `unknown` primitive whose `csharpType` names a type with no schema mapping, fails with `RIV2005` instead of shipping an untyped `{}`. "Any JSON value" (TypeScript `unknown`, `object`, `JsonElement`, `JsonDocument`, and the `JsonNode` family including `JsonValue`) still maps to `{}`, now with no diagnostic at all.
- CLI: a preserved component whose own `$ref` dangles (the source OpenAPI was broken) fails emission with `RIV2005`, naming the component and where it's referenced. Rivet used to invent an untyped stand-in. The check runs over the finished document, so a preserved field such as an `encoding` header is covered, and a `"$ref"` key inside an example, default, const, enum or `x-` extension is data, not a reference.
- CLI: a `[RivetEndpoint]`, `[RivetClient]` or abstract contract method with no HTTP verb, or no route template on the action or its class, stops generation with `RIV1100`. It used to vanish from the spec.
- CLI: a generic used with more type arguments than its template declares fails with `RIV2006`. The extra arguments used to be dropped.
- CLI: two routes that differ only in parameter names (`/tasks/{id}` and `/tasks/{taskId}`) stop generation with the new `RIV2013`. OpenAPI reads them as one path, and Rivet used to write both keys into an invalid document.
- CLI: `RIV2001` fires only for a producer-pinned `componentId` that lands on a different schema, and it's an error.
- `Rivet.Attributes`: `RivetVendorExtensionAttribute` is now `RivetPreservedFieldAttribute`, because it carries documentation fields as well as `x-` extensions. Re-import to regenerate.

#### Fixes

- CLI: `TimeSpan` maps to the string System.Text.Json writes, the invariant `"c"` format (`[-][d.]hh:mm:ss[.fffffff]`), with a matching `pattern` and `x-rivet-csharp-type: TimeSpan`, including as a dictionary key. It used to be an untyped `{}` with `RIV1009`, which is retired.
- CLI: `Int128`, `UInt128` and `Half` map to the numbers System.Text.Json writes (`integer`, `integer`, `number`, each with `x-rivet-csharp-type`). They used to be `{}`.
- CLI: a DataAnnotations constraint on a positional record parameter without `[property:]` now reaches the spec. That's where MVC validation reads it, so the spec used to be looser than the wire. `[RivetConstraints]` can sit on the parameter too. A derived record's parameters are read from its own constructor, so a base record's attributes don't leak in.
- CLI: a record's get-only property bound by its primary constructor is no longer marked `readOnly`. Rivet never recognised the primary constructor, but System.Text.Json reads the property through it. `readOnly` now follows System.Text.Json's own constructor choice: `[JsonConstructor]`, else a struct's default constructor, else a class's public parameterless constructor, else its only public constructor.
- CLI: a tagged-union variant whose `{Base}_{Tag}` name is already taken, or whose tag PascalCases like a sibling's, gets a numeric suffix and `$ref`s its own schema. It used to point at whoever owned the name.
- CLI: `--from-openapi` no longer drops things without saying so, and carries most of them through instead. Path-item `summary` and `description`, operation `externalDocs`, response and component `links`, media-type `encoding`, `info.summary` and `jsonSchemaDialect` ride along as preserved fields and come back out at the same pointer. A query parameter's `allowReserved` is imported and emitted. What still can't be carried is reported: a parameter with `content` instead of a `schema` (`RIV3025`), callbacks (`RIV3027`), and webhooks and `components.pathItems` (`RIV3028`).
- CLI: a response header with an empty name, or a second spelling of one already declared on that status (`X-Rate` and `x-rate`), leaves a `[rivet:unsupported header …]` marker instead of quietly disappearing.

### Part 2: promises Rivet now checks

#### Breaking

- `Rivet.Attributes`: `.ToResult()` and `.ToActionResult()` refuse host JSON options that would put a different wire on the spec. The spec assumes System.Text.Json's web defaults, so another naming policy, a `DictionaryKeyPolicy`, anything in `Converters` (Rivet's own enum converters included), `NumberHandling` that writes strings, an ignore condition, `IgnoreReadOnlyProperties`/`Fields`, `IncludeFields`, a `ReferenceHandler`, `UnmappedMemberHandling.Disallow`, `RespectRequiredConstructorParameters`, or a resolver that isn't the default one or a source-generated context now throws `RivetContractViolationException` naming each difference. Before, the docs called all this "invisible to the spec" and shipped the wrong spec anyway. Declare the behaviour on the types instead. So is a source-generated context declared with `[JsonSourceGenerationOptions(UseStringEnumConverter = true)]`, which builds the string converter into each enum it covers where the options never show it. Settings that only loosen reading or change formatting (case-insensitive names, trailing commas, indenting, the encoder) are left alone. Each options instance is frozen and compared once; ASP.NET freezes them on its first write anyway.
- `Rivet.Attributes`: polymorphism added through `TypeInfoResolver` modifiers is refused with everything else above. 0.45.0 accepted it, but the spec never showed the `$type` or the extra members. Use `[JsonPolymorphic]`/`[JsonDerivedType]`.
- `Rivet.Attributes`: a response header declared `required: true` is checked. A response at that status written without it throws, naming the header and the status. Set it on `HttpContext.Response.Headers` before returning; a file's `entityTag:`, `lastModified:`, `downloadName:`, `inline:` and `enableRangeProcessing:` count for the headers they produce, and a text body counts for `Content-Length`. A header a middleware only adds in `OnStarting` arrives too late to count.
- `Rivet.Attributes`: the Rivet enum converters read exactly the names the spec lists, case-sensitively, on every runtime. The member name in another casing, and .NET 8's `"0"`, are now a `JsonException`, and so are dictionary keys. A refusal names the JSON type that was sent ("A JSON object") and the names that would be accepted. Writing is unchanged. 0.48.0 said the member name was still read in any casing; that's no longer true. They now derive from the new `RivetStringEnumConverter<T>` (a `JsonConverterFactory`) instead of `JsonStringEnumConverter<T>`.
- CLI: `RIV4005` checks Azure Functions handlers. The worker reads a route value as JSON, so an enum with string wire values binds no name at all; use a plain enum or bind a `string`.

#### Fixes

- CLI: `--check` follows a `Match` arm held in a local or written as a local function, and a terminal handed to a helper, as in `return Done(endpoint.Success(x))`, no longer leaves the binding an `OrphanedBinding`.
- CLI: `RIV4005` and `RIV1110` stop missing enums ASP.NET binds piece by piece: an `[ApiController]` complex type with a `[FromQuery]` or `IFormFile` member, every complex parameter once `SuppressInferBindingSourcesForParameters` is set, MVC types nested at any depth, and minimal-API `[FromForm]` types (whose mapper ignores case).
- CLI: `--check` no longer overflows the stack on a local function that passes itself to the call it returns (`IResult Attempt() => Retry(Attempt);`).
- CLI: `RIV4005` and `RIV4006` bind the way the host does in three more places: minimal APIs read `StringValues` from the query on a body-less verb, a type with only a `[TypeConverter]` is a simple value on MVC but not on minimal APIs, and on MVC `Name =` on a complex `[From*]` parameter prefixes its members (`?f.Search=`).

### Part 3: inputs, security and the corpora

#### Breaking

- `Rivet.Attributes`: security reads the way OpenAPI means it. `.Secure(scheme, scopes...)` adds one way in, so calling it twice gives two alternatives. `.AndSecure(...)` adds a scheme the same caller also needs, and `.OrAnonymous()` makes credentials optional. `.Secure("admin")` reads exactly as before. The numbered `.SecurityRequirement(order, ...)` calls are gone; re-import, or rewrite them as `.Secure`/`.AndSecure`. Security stays spec-only: nothing checks it at runtime.
- CLI: contract JSON (`--from`) keeps an endpoint's security in one place: `security` is now the full `{ "alternatives": [{ "schemes": [{ "name", "scopes" }] }] }` list. The old `{ isAnonymous, scheme }` shape and the separate `securityRequirements` property are gone, so rivet-ts has to write the new shape. One scheme listed twice in an alternative is refused as invalid contract JSON.
- CLI: in contract JSON an endpoint parameter's deprecation flag is `deprecated`, as `rivet-contract-schema.json` always said, not `isDeprecated`. `--from` JSON using the schema's name used to be ignored. The schema itself now accepts every field Rivet writes (`minProperties`/`maxProperties`, scalar `format`/`required`/`enum`, the provenance references, param source `cookie`, `schemaDescription` and more), so rivet-ts and rivet-php need its new copy.
- CLI: contradictory security calls (`.Anonymous()` alongside `.Secure()`, or `.AndSecure()` with nothing to join) fail with the new `RIV1114`. Before, one call quietly won.
- CLI: `RIV4006` is an error, so an app whose handlers bind inputs differently from the contract now fails `--check`.
- CLI: a `SuppressInferBindingSourcesForParameters` assignment that isn't a compile-time constant stops `--check`, and generation, with the new `RIV4007`, naming the file and line. Whether MVC infers binding sources decides what every parameter binds, so `RIV4005`, `RIV4006` and `RIV1110` used to answer on a guess.
- CLI: `--from-openapi` merges paths that differ only in parameter names (`/deployments/{id}` beside `/deployments/{idOrUrl}`, which OpenAPI forbids) into the first one, with the new `RIV3029`. The later operation's C# route and parameters take the first path's names. Nothing changes on the wire, because path parameter names are never sent. Paths that can't merge cleanly (a shared method, path-level parameters or servers on the first, a repeated parameter name) are left alone and stop generation with `RIV2013`.
- `Rivet.Attributes`: `RequestExampleJson`/`ResponseExampleJson` take a nullable `json` plus `summary:` and `description:`, and `RivetSchemaRef` takes an optional pointer and can repeat. Contract JSON's `endpointExample` gains `summary`/`description` and a form with no value. Re-import to regenerate.

#### Features

- CLI: `--check` compares each handler's bound inputs with its contract's and fails with `RIV4006` when they disagree: an input the handler binds that the contract never declares, one the contract declares that the handler never binds, or one bound from the wrong place. It reads binding the way ASP.NET does, inference and `Name =` included, so it catches an `[AsParameters]` member renamed with `[JsonPropertyName]` (the spec says `?q=`, ASP.NET reads `?Text=`) and an `[ApiController]` GET that takes its query record from the body. A `.FormEncoded()` body is compared field by field under its wire names, and a declared cookie is reported unless the handler reads the request. A handler with `HttpRequest` or `HttpContext` in reach (a parameter, `Request`, `ControllerContext.HttpContext`, `IHttpContextAccessor.HttpContext`) is trusted to read the rest by hand. The `Authorization` header, a `.QueryAuth()` token and an apiKey scheme's header or query parameter belong to security. Azure Functions handlers aren't compared.
- Corpora: stripe, slack, vercel, github and discord join the round-trip gate, which now proves 21 of the 25 committed specs survive import, compile and re-emit. The fixes that got them there are below.

#### Fixes

- CLI: `components.headers` survive import, and a header `$ref` stays a `$ref` on operation and component responses. They used to vanish, leaving component responses pointing at nothing.
- CLI: an Example Object keeps its `summary` and `description`, and one that is only a summary comes back as a whole example rather than a `missing-value` marker. A `$ref`'d example keeps its summary and description beside the `$ref`, and an example value shaped like `{"$ref": …}` stays data.
- CLI: an enum is a set. A repeated member collapses to one instead of giving the C# enum two members with one wire value (`RIV1106`).
- CLI: a `null` enum member survives import, separately from nullability. Both rules hold under a property or response named `default` or `example`, which used to be mistaken for example values.
- CLI: array items and map values in a typed record keep their `$ref` to a named scalar, and a nullable use of a component, enum or brand that already admits null is referenced bare. The old `oneOf: [$ref, null]` matched null twice, so `oneOf` rejected null outright.
- CLI: `minProperties`/`maxProperties` survive on typed dictionaries instead of vanishing.
- CLI: OpenAPI 3.1's titled-const `oneOf` (`{ title, const }` per member) imports as an enum named by its titles. It used to be a union of identical slots nobody could tell apart, with a `RIV3015` each.
- CLI: a named boolean or number enum keeps its members, and the properties using it keep their `$ref`.
- CLI: a branded scalar keeps `readOnly`, `example` and its other annotations.
- CLI: a discriminator mapping into another file is dropped with `RIV3005`. Re-emitted, it used to crash the next import. A mapping value counts as a schema name only when a schema component has that name, as OpenAPI 3.1.1 says.
- CLI: a `$ref`'d path item's summary, description, `externalDocs` and callbacks are preserved, or reported, under the referencing path.
- CLI: an imported discriminator variant pinned to a component the import also kept verbatim `$ref`s that copy, instead of failing `RIV2001` against a shape rebuilt from C# without the descriptions.

### Docs

- Limitations, Runtime Validation, Contract Coverage, the 0.42 migration guide, the import profile, the type mapping and the attributes reference lose every sentence that excused one of the gaps above, and describe the check or the refusal instead.
- Diagnostics: the error list and every changed row are updated; `RIV2003`'s registry text no longer claims "the later definition wins". `RIV1009` joins the retired IDs, and so does `RIV3002`, which nothing had emitted since 0.41.0: the importer has kept every security alternative and its scopes since then.
- The Route Definition API page gets a Security section covering OR, AND, scopes and optional auth. The import profile, limitations and round-trip pages stop claiming that multi-scheme security and scheme definitions get lost on import.
- The import profile no longer calls the corpus gate "not reproducible CI proof": the corpora are committed and hash-pinned, and the gate runs in every release's `dotnet test`. It also stops listing parameter `style`/`explode`/`allowEmptyValue` as unsupported in the same bullet that said they were supported.
- The import profile counts 21 of 25 verified corpora, and its new "Outside the gate" section names exactly what keeps bitbucket, jira, digitalocean and cloudflare out.
- The endpoint builder reference no longer calls `.WithResponseHeader(required:)` or `.ProducesContentType` spec-only.
- Diagnostics: `RIV1101` joins the retired IDs (registered in 0.42.0, never emitted), and `RIV3019`, which the importer has written since 0.41.0 for a Swagger 2 `host` without `schemes` or the reverse, gets a registry entry, a row and a warning category. The page no longer claims most diagnostics are warnings.
- Round-trips, Limitations and Runtime Validation stop listing links, header schemas and parameter styles as lost on import, and stop calling custom serializer settings and unregistered polymorphism invisible. Type Mapping lists `Int128`, `UInt128`, `Half` and the any-JSON types.

## 0.48.0 — 2026-10-21

### Features

- `Rivet.Attributes`: `File(Func<Stream, Task> writer, ...)` serves a file the handler writes as it goes, such as a live transcode piping into the response. Every `File(...)` rule still applies before the writer runs: a declared binary success, a content type the contract covers, a concrete type for a media range, and a well-formed entity tag. `nosniff` and the inline disposition are sent as for any file. There is no `enableRangeProcessing`, because a body written as it goes has no byte ranges. Works with `.ToResult()` and `.ToActionResult()`, and `--check` counts it like any other `File(...)`.

### Fixes

- CLI: `--check` accepts a contract field's `.Route` as a minimal-API route, as in `app.MapGet(MembersContract.Health.Route, ...)`, which the Contracts guide has always recommended. Before, any route that wasn't a compile-time constant was reported as `RouteMismatch`, so you had to keep a `const string` next to every contract route. `MapGroup` prefixes still count, so a grouped route that doesn't match the contract is still reported.
- CLI: `--check` follows two common ways of returning a terminal that it used to miss, and reported as `MissingImplementation` and `OrphanedBinding`. The first is lambda arms, as in `return outcome.Match(ok => endpoint.Success(ok).ToActionResult(), ...)`, sync or async, in an action or a minimal-API handler. The second is one adapter around a whole switch or `?:`, directly or through a local holding it, as in `return (result switch { ... }).ToActionResult()`. A lambda counts only when it's passed straight to the call the handler returns, such as a `Match` arm; one buried in an argument, as in `Ok(items.Select(...))`, doesn't. A terminal that reaches the adapter through a helper still never counts.
- CLI: `--check` no longer counts a static method on a controller as an MVC implementation. MVC never routes a static method, so it was crediting coverage to an action that never runs; the field now shows as `MissingImplementation`, and a `Bind` in it as `OrphanedBinding`.
- CLI: a bound endpoint the handler hands to a helper whose answer it returns, as in `return Done(endpoint.Refuse(reason))` or a `Match` arm doing the same, is no longer an `OrphanedBinding`. The docs have always said a helper may take the bound endpoint. `--check` looks for it through the same `await`, casts, `switch`, `?:` and locals it follows for terminals, and counts a C# 14 extension block's receiver as well as a classic extension's. Coverage is unchanged: a field still needs a terminal the handler returns itself.
- `Rivet.Attributes`: a stream file the adapter refuses, because the host already started the response or set another status, is now disposed. Before, nothing disposed it.
- Docs: `RIV3004` and `RIV3013`, retired in 0.42.0 but still registered with a "Retired" row, are gone from the registry and get tombstones like every other retired ID. `RIV3007` gets the tombstone it was missing, and the tombstones move to their own section at the end of the diagnostics page instead of sitting under extraction.
- Tests: each target framework's tests run on that framework's runtime. A repo-wide `RollForward=LatestMajor` had been running the net8.0 and net9.0 runs on .NET 10, which hid that .NET 8 still reads `"0"` for a strict enum. Only the CLI rolls forward now, so it still runs on whatever newer .NET a consumer has.

### Breaking

- `Rivet.Attributes`: on MVC, contract files (bytes, streams and physical paths) now go through the same ASP.NET file results that minimal APIs and writers already used, rather than MVC's `FileContentResult`, `FileStreamResult` and `PhysicalFileResult`. Ranges, conditional requests, disposition and headers come out the same on both hosts, and the tests pin each one on both. The catch: if your app replaced MVC's file-result executors, Rivet files no longer go through them.
- `Rivet.Attributes`: `RivetLowerCaseEnumConverter`, `RivetCamelCaseEnumConverter`, `RivetSnakeCaseEnumConverter` and `RivetKebabCaseEnumConverter` refuse integers. A JSON `0` for one of these enums is now a `JsonException` on every runtime instead of being read as the member with that value, and so is a numeric string `"0"` from .NET 9 on (.NET 8's System.Text.Json still reads it). The C# member name is still read in any casing, as System.Text.Json always has. An enum with no converter is still an integer, and System.Text.Json's own `JsonStringEnumConverter` is unchanged. Route, query, header and form parameters are bound by ASP.NET, not by these converters, so this doesn't change them. An app that registered a global strict `JsonStringEnumConverter` to get this behaviour can drop it only if every enum it serializes carries a Rivet converter: a global converter also turns enums with no converter into strings, and dropping it makes those integers on the wire.
- CLI: an enum parameter bound from the route, query, header or form now has to be bindable with every wire value the spec lists. The spec has always advertised the converter's names for it, but ASP.NET binds these values itself: minimal APIs need each name to equal the member name exactly, MVC needs it to equal ignoring case. So a camelCase or lowercase converter advertised values a minimal API answers with 400, and snake, kebab or a rename that changes more than the casing did the same on both hosts. `--check` now refuses that with `RIV4005` for a handler implementing a contract (Azure Functions handlers aren't checked), and generation refuses it with `RIV1110` for an annotated action (`[RivetEndpoint]` or `[RivetClient]`; a static `[RivetEndpoint]` handler gets the minimal-API rule). Use a plain enum, the built-in `JsonStringEnumConverter<T>` with no renames, or bind a `string` and parse it yourself. A contract on its own isn't checked at generation, because generation can't see how the handler binds.

### Docs

- Contract Coverage: a "Helpers are fine" section. The spec comes from the contract, so an `.Error(...)` or a 404 guard can live in a shared helper, and `--check` only needs each handler to return one terminal on its contract.
- Limitations: an "Enum parameters are bound by ASP.NET" section, with what each host accepts for an enum in the route, query, header or form, what Rivet checks, and the three ways to fix a failing check. The converter docs no longer claim a JSON body accepts exactly the spec's names: integers are refused, and the member name still gets through in any casing.

## 0.47.0 — 2026-10-20

### Features

- `Rivet.Attributes`: `.ToActionResult()` now hands back a public `RivetActionResult` (still typed as `IActionResult`), so an MVC result filter can read what a handler returned. It implements `IStatusCodeActionResult`, and `Value` is the payload passed to `Success(...)` or `Error(...)` (`null` for a bodyless response or a file). Before, the result was private and gave a filter neither its status nor its body. Both are read-only: Rivet still writes the response, and status, headers and body on the wire are unchanged. For a file, `StatusCode` is the declared status; a range or conditional request can still make the host send 206, 304, 412 or 416.

## 0.46.0 — 2026-10-03

### Features

- `Rivet.Attributes`: a file response declared with a media range (`.ProducesFile("*/*")`, `image/*`) now serves any concrete type inside it: `File(..., contentType: "application/pdf")` sends `application/pdf`. Before, a range only matched itself, so files whose type is known only at runtime (stored uploads) could not use the File terminal. An exact declaration wins over a range. A range rejects a type outside it, a wildcard or malformed runtime type, and an omitted `contentType`, which used to send the literal range as `Content-Type`.
- `Rivet.Attributes`: `File(...)` takes `inline: true`, which sends `Content-Disposition: inline` and keeps the download name. Before, a download name always made the file an attachment.
- `Rivet.Attributes`: every file response sends `X-Content-Type-Options: nosniff`.

### Breaking

- `Rivet.Attributes`: the six `File(...)` overloads gained the optional `inline` parameter. Source calls are unchanged; assemblies compiled against 0.45.x must be rebuilt.

## 0.45.1 — 2026-09-30

### Fixes

- Release binaries: the `rivet-<rid>.tar.gz` binaries are no longer single-file. `--project` crashed because the MSBuild build host was bundled away from `BuildHost-netcore/`, and loose `.cs` files crashed resolving framework references. The tarball is now the whole self-contained publish directory, with `rivet-<rid>` still at its root. On Linux, the binary also looks for an SDK in `/usr/share/dotnet`, `/usr/lib/dotnet` and `~/.dotnet` when `DOTNET_ROOT` is unset, so `--project` works with a distribution-packaged or user-local SDK. The release workflow runs the extracted binary in every input mode on linux-x64 and osx-arm64 before uploading.
- CLI: `--help` and `-h` print usage to stdout and exit 0. Before, they printed usage after `error: unknown flag` and exited 1.
- Tooling: the Taskfile runs `pnpm` directly instead of `corepack pnpm` (Node 25+ no longer ships corepack), and `docs/package.json` pins the same `packageManager` as the root so a newer global pnpm does not rewrite `docs/pnpm-workspace.yaml` or fail on esbuild's build script.

### Docs

- CONTRIBUTING: a Prerequisites section, the real clone URL, `task install` as the first step (a fresh clone failed about 30 tests until `Rivet.Tests/js` had its node tooling), and the Taskfile tasks.
- README: a Prerequisites section, a `dotnet new webapi` step before `dotnet add package`, and C# snippets that compile as pasted (`using` directives, the DTOs they use, a complete controller). The `--security admin=bearer` example now says the first scheme is the document-wide default, so it secures every endpoint that is not `.Anonymous()`.
- Getting Started installs `Rivet.Attributes` without `--version "*"`, matching the README.
- Removed stale references: the FunctionsApi sample's "0.41.0" and `Rivet.Tests/js`'s nonexistent `ZodValidatorEmitterTests`.

## 0.45.0 — 2026-09-29 (breaking)

- `Rivet.Attributes`: removed the unused `RouteDefinitionBase.IsFileUpload` getter.
- Import: an operation with `security: []` now scaffolds `.Anonymous()` instead of `.SecurityRequirements()`. Both re-emit `security: []`.
- `Rivet.Attributes`: removed the protected `RouteDefinitionBase.BeginMutation()` and `CopyStateTo()` helpers. Builder state is now one immutable record behind a private gate.
- `Rivet.Attributes`: removed the 18 five-parameter `File(content, downloadName, enableRangeProcessing, lastModified, entityTag)` overloads on `RouteDefinition`, `RouteDefinition<T>`, `FileRouteDefinition` and the three `Bound*` types. Source calls still bind to the six-parameter overload (`contentType` defaults to `null`); assemblies compiled against the old overloads must be rebuilt.
- `Rivet.Attributes`: removed the test-only getters on `RouteDefinitionBase` (`EndpointSummary`, `EndpointDescription`, `IsAnonymous`, `SecurityScheme`, `FileContentType`, `IsFormEncoded`, `BinaryRequestContentType`, `RequestContentType`, `ResponseContentType`, `IsQueryAuth`, `QueryAuthParameterName`, `RouteErrorResponses`, `ResponseHeaders`, `SuccessStatusCode`, and the protected `SuccessStatus`) and the `RouteResponseHeader` record. Spec-only builder methods (`Summary`, `Description`, `Anonymous`, `Secure`, `QueryAuth`, `WithResponseHeader*`, the example, security-requirement, request-content and `Parameter<T>` markers) no longer record anything at runtime; Rivet.Tool reads them from syntax. They still throw after publication.
- `Rivet.Attributes`: declaring the same response header twice for one status no longer throws at runtime.
- `Rivet.Attributes`: `RouteErrorResponse` and `RivetUnionJsonConverter<T>` are now internal (`[RivetUnion]` still constructs the converter).
- `Rivet.Attributes`: a subtype payload where a concrete type is declared is now rejected when the result executes, not when `Success(...)`/`Error(...)` is called. The check uses the host's serializer options, so polymorphism configured through a `TypeInfoResolver` is honoured, not only `[JsonPolymorphic]`/`[JsonDerivedType]` attributes.
- `Rivet.Attributes`: declared response media types match on the type without parameters, so `text/csv; charset=utf-8` and `text/csv` are one representation. A body response whose selected content type is malformed is now a contract violation.
- Import: every disambiguated name now uses one `Name_2`, `Name_3`… scheme. Synthetic types that used to be `Foo2` are now `Foo_2` (for example, slack's `InfoResponseDefaultContent12` is now `InfoResponseDefaultContent1_2`). Enum members and contract fields also skip a suffix that the spec already authored.
- Import: inline schemas that differ in `oneOf`/`anyOf`/`allOf`/`const`/`not` now get distinct synthetic types instead of silently sharing the first one.
- Import: a Swagger 2 `basic` security definition now imports as HTTP `basic`; before, it was refused.
- Import: a malformed spec (invalid JSON, missing required fields) now exits 1 with `error: invalid OpenAPI document: …` instead of a stack trace.
- Analysis: attributes are matched by symbol, not by simple name. A same-named attribute from another namespace (for example a custom `RequiredAttribute`) no longer counts as the Rivet, DataAnnotations or System.Text.Json attribute.
- Analysis: nested types are now discovered, so a `[RivetContract]`, `[RivetType]`, `[RivetClient]` or `[RivetEndpoint]` class nested in another class is no longer silently skipped.
- Analysis: a C# `required` field (a `[JsonInclude]` field) is now required in the schema, as a `required` property already was.
- Analysis: a contract field's builder chain is read through Roslyn operations. A chain that does not start at a `Define` member is no longer read, and a call in the chain that is not a Rivet builder method (such as a user extension named `Returns`) is refused instead of being interpreted by name.
- `--from` contract JSON: the reader now enforces the members `rivet-contract-schema.json` requires on type nodes (`kind`, a primitive's `type`, `inner`, `element`, `values`, and so on) and the `type` of every param, response header and property. A missing one now fails with exit 1 and a JSON error. Before, it was either silently emitted as an untyped `{type: object}` or crashed with a stack trace. Schema-valid contracts, including rivet-ts output, are unaffected.
- OpenAPI emission: a `[RivetDefault]`/`[RivetExample]` value, or a schema-metadata default/example, that is not a JSON literal is now refused with exit 1. Before, property values fell back to a raw string and the other paths crashed with a stack trace.
- Diagnostics: retired `RIV3007` (alias `$ref` cycle). Nothing emitted it; alias cycles are reported as `RIV3001`. The ID is not reused.
- `Rivet.Attributes`: `[RivetConstraints]` keeps only `MultipleOf` and `UniqueItems`. `ExclusiveMinimum`/`ExclusiveMaximum` are gone; use `[Range(…, MinimumIsExclusive = true, MaximumIsExclusive = true)]`. `MinItems`/`MaxItems` are gone; use `[MinLength]`/`[MaxLength]`/`[Length]` on the collection. Rivet reads `[MinLength]`/`[MaxLength]`/`[Length]` as `minItems`/`maxItems` on an array property (before, `[MaxLength]` on a list emitted a string `maxLength`) and reads `[Length]` at all. Import scaffolds the DataAnnotations form. A schema that declares both the inclusive and the exclusive bound of one side imports the tighter one.
- CLI: `--project` is only ever a project file. `--project Contracts.cs` used to fall back to compiling the positional `.cs` files; it now tries to load `Contracts.cs` as a project and fails. Pass `.cs` files positionally. A positional `.csproj` is the project wherever it appears in the argument list, not only first.
- `Rivet.Attributes`: removed the implicit conversions from every route-definition type to `Define` (they returned `default!`). Declare contract fields with the builder's own type, for example `public static readonly RouteDefinition<TaskDto> Get = Define.Get<TaskDto>("/tasks/{id}");`. Rivet no longer discovers `Define`-typed fields.
- `Rivet.Attributes`: removed the 22-argument `RivetGeneratedSchemaMetadataAttribute` constructor. Rivet no longer reads the short form; re-import to regenerate code that used it.
- `Rivet.Attributes`: `Error` and `File` terminals are declared once, on the new abstract `TerminalRouteDefinitionBase<TSelf>` (base of `RouteDefinition`, `RouteDefinition<T>` and `FileRouteDefinition`) and `BoundRouteDefinitionBase` (base of the three `Bound*` types). Source calls are unchanged; assemblies compiled against the old declaring types must be rebuilt.
- `Rivet.Attributes`: removed the `FileRouteDefinition.ContentType(…)` and `FileRouteDefinition<TInput>.ContentType(…)` aliases. Use `.ProducesFile(…)`. Import now scaffolds `.ProducesFile("…")` on `Define.File(...)` endpoints.
- Analysis: a contract endpoint that declares the same response header twice for one status (case-insensitively, e.g. `ETag` and `etag`) now fails with `RIV1109`. Before, both spellings were emitted.
- `Rivet.Attributes`: removed the no-argument `.SecurityRequirements()` builder method; it declared the same `security: []` as `.Anonymous()`. Use `.Anonymous()`.
- OpenAPI emission: an inline object whose derived component name is taken and no descriptive name fits is now named `Name_2`, `Name_3`… (was `Name2`), the same scheme import uses.
- Import: a response header declared on both a range status (`4XX`) and `default` now imports for both. Before, the second was dropped because both statuses shared the numeric key 0.
- Analysis: nullability no longer makes an object-schema property optional. System.Text.Json writes `null`, so a `T?` property is now `required` with a `T | null` type; it was omitted from `required` (clients saw `x?: T | null`). A property is optional only with `[RivetOptional]` or `[JsonIgnore(Condition = WhenWritingNull/WhenWritingDefault)]`. This includes multipart input records, whose nullable parts now need `[RivetOptional]` to stay optional. Query, header and form parameters keep binder semantics (nullable ⇒ optional). `[Required]` and the C# `required` keyword no longer affect requiredness anywhere: object properties are required by default, and the emitter already treated every nullable parameter as optional. **Migration:** add `[RivetOptional]` to each nullable property clients may omit. Import already scaffolds `[RivetOptional]` for every property a spec leaves out of `required`, so imported code round-trips unchanged.
- `--from` contract JSON: an inline-object property without an `optional` flag is now required even when its type is nullable (the nullable ⇒ optional fallback for older IR is gone). rivet-ts always writes the flag for nullable properties, so its output is unaffected.
