# Diagnostics Reference

Every warning Rivet writes to stderr, and every error it stops on except a command-line usage
error, carries a stable ID in a canonical, machine-parseable format:

```
warning RIV1003: <message>
error RIV2002: <message>
```

IDs are stable across releases — grep, baseline, or suppress by ID, never by
message text. A **warning** lets processing carry on; an **Error** is fatal and exits
`1`. There are twice as many errors as warnings these days, because most of what used
to be a warning about a wrong spec now refuses to write one. The errors are
`RIV1001`, `RIV1002`, `RIV1004`, `RIV1006`, `RIV1007`, `RIV1010`, `RIV1014`, `RIV1015`, `RIV1016`, `RIV1017`, `RIV1018`, `RIV1019`, `RIV1020`, `RIV1021`, `RIV1022`, `RIV1023`, `RIV1100`, `RIV1102`, `RIV1103`, `RIV1104`, `RIV1106`, `RIV1107`, `RIV1108`, `RIV1109`, `RIV1110`, `RIV1111`, `RIV1112`, `RIV1113`, `RIV1114`, `RIV1115`, `RIV1116`, `RIV1117`, `RIV1118`, `RIV1119`, `RIV1120`, `RIV1121`, `RIV1122`, `RIV1123`, `RIV1124`, `RIV1125`, `RIV1126`, `RIV2001`, `RIV2002`, `RIV2005`, `RIV2006`, `RIV2007`, `RIV2008`, `RIV2009`, `RIV2010`, `RIV2011`, `RIV2012`, `RIV2013`, `RIV2015`, `RIV2016`, `RIV2017`, `RIV2018`, `RIV2020`, `RIV2021`, `RIV3032`, `RIV4005`, `RIV4006`, `RIV4008`, `RIV4009`. Coverage
warnings also exit `1` whenever `--check` is used, with or without `--output`; other
warnings do not change the exit code.

The ID ranges follow the pipeline stages:

| Range | Stage |
|---|---|
| `RIV1xxx` | Extraction (Roslyn walkers) |
| `RIV2xxx` | Emission (OpenAPI emitter, contract JSON reader) |
| `RIV3xxx` | Import (`--from-openapi` scaffold) |
| `RIV4xxx` | Coverage (`--check`) |

Within the extraction range, `RIV1024`-`RIV1099` were once reserved for the
`rivet/php` sibling runtime, which has since been dropped. The block stays empty and
is never reused.

**Markers are not diagnostics.** The `// [rivet:unsupported …]` marker comments
that `--from-openapi` writes into scaffolded source are part of the generated
code, not stderr diagnostics — they have their own grammar and carry no RIV ID.
See the [Import Profile](/reference/import-profile) marker table.

The registry (`Rivet.Tool/Diagnostics.cs`) and this page are cross-checked in
both directions by the test suite (`DiagnosticsTests`) — every registered ID
must have a row here with the same severity, and every row here must be a registered ID.

## RIV1xxx — extraction

| ID | Severity | Trigger | Remediation |
|---|---|---|---|
| `RIV1001` | Error | Contract endpoint field is not `static readonly`. Rivet reads the spec from the field's initializer, so a field that can be reassigned, or exists once per instance, could serve a different definition at runtime than the one in the spec. | Declare the `Define` field as `public static readonly`. |
| `RIV1002` | Error | Response example targets a status code the contract endpoint does not declare — the spec has no response to put it on, so generation fails rather than quietly losing it. Also raised when an example names a media type its `.ResponseContent(...)` status doesn't declare, or names none when that status declares several. An example without a media type takes the status's own (or the success body's `.ProducesContentType(...)`). | Declare the status on the endpoint (`.Returns(...)`, `.Status(...)` or `.ResponseContent(...)`) or fix the example's status code. |
| `RIV1003` | Warning | `[JsonPropertyName]` on a route-bound property is ignored for route interpolation — the contract param keeps the route name. | Align the route token and the property name, or accept that the route name wins for path params. |
| `RIV1004` | Error | Response example targets a status code the controller endpoint does not declare — the spec has no response to put it on, so generation fails rather than quietly losing it. | Declare the response status on the action (e.g. `[ProducesResponseType]`) or fix the example's status code. |
| `RIV1006` | Error | Unmapped typed result branch in `Results<...>`, or an action with no declared success response — generation fails instead of guessing or omitting the response. | Declare the branch with a fixed-status typed result or explicit `[ProducesResponseType]`; declare the success response with `[ProducesResponseType(typeof(T), 200)]`, a concrete payload return, or a fixed-status typed result. |
| `RIV1007` | Error | Two walked types share a simple name: different namespaces, nesting, or generic arity (`Result` and `Result<T>`). Schema names are global and built from the simple name alone, so generation fails and names both types. A walked type that takes the name of a `[RivetGeneratedSchema]` component is the same collision: the type would replace the generated schema. Only the enum or `[RivetScalar]` brand the schema annotates may share its name. | Rename one of the two types. If the other is a generated schema, rename your type or re-import. |
| `RIV1008` | Warning | A `[Range]` bound could not be parsed — the range constraint is skipped. | Use numeric `[Range]` bounds the walker can evaluate. |
| `RIV1010` | Error | `BigInteger` has no System.Text.Json converter: it serializes as an object of its `IsZero`/`Sign`/… properties and can't be read back, so no schema describes it honestly. | Expose the value as a `string` of digits, or as `long` or `decimal` when the range allows. |
| `RIV1013` | Warning | Dictionary key type has no contract representation (supported: `string`, enums, string-backed brands, string-serializable primitives like `Guid`/`DateTime`/`char`/numerics) — keys are emitted as unconstrained strings. | Use a supported key type, or accept the unconstrained string keys. |
| `RIV1014` | Error | A `[JsonDerivedType]` registration a string-discriminated `oneOf` can't represent. An int tag isn't a string, a tagless registration writes no discriminator at all, and a registered type that isn't a named class, struct or record (`typeof(int[])` compiles, sadly) has no variant schema to point at; System.Text.Json throws on that last one anyway. | Register only types that derive from the base, each with a string tag: `[JsonDerivedType(typeof(Circle), "circle")]`. |
| `RIV1015` | Error | `[JsonPolymorphic]` base type has no `[JsonDerivedType]` registrations. System.Text.Json doesn't shrug and write the base: it throws ("should specify at least one derived type") the moment it meets the type, so no host can serve it and there's no honest schema to write. | Register the derived types with `[JsonDerivedType(typeof(Derived), "tag")]`, or remove `[JsonPolymorphic]`. |
| `RIV1016` | Error | `[JsonPolymorphic]` sets `UnknownDerivedTypeHandling` to `FallBackToBaseType` or `FallBackToNearestAncestor`. The host then writes a derived type it never registered as its base (or nearest registered ancestor), and the spec's `oneOf` admits only the registered types, so the document would reject a payload the server actually sends. Generation stops rather than publish that. Setting it to `FailSerialization`, the default, is fine. `IgnoreUnrecognizedTypeDiscriminators = true` is refused for the same reason in the other direction: the host reads a body with an unknown tag as the base, which the `oneOf` rejects. | Remove the setting, so an unregistered type fails to serialize and an unknown tag fails to read, as System.Text.Json does by default, and register every type the API really sends or accepts with `[JsonDerivedType]`. |
| `RIV1017` | Error | `.WithResponseHeader()` targets a status code the contract endpoint does not declare — the spec has no response to put it on, so generation fails rather than leaving out a header the handler sends. | Declare the status on the endpoint (`.Returns(...)`, `.Status(...)` or `.ResponseContent(...)`) or fix the header's status code. |
| `RIV1018` | Error | `[RivetUnion]` wrapper has no variant properties, so there is no union to emit. | Give the wrapper one optional property per variant (the shape the importer generates), or remove the attribute. |
| `RIV1019` | Error | Route token has no typed declaration: no matching property on the endpoint's input type (after normalized matching: case-insensitive, `_`/`-` stripped), no `.Parameter<T>(name, "path", ...)`, no type constraint, or, on a `[RivetEndpoint]` action, no action parameter. Its type is unknown, and the spec would have to guess `string`, looser than whatever the handler binds, so generation fails instead. | Add a matching property to the input type, a type constraint to the route (`{id:guid}`, `{id:int}`), or a `.Parameter<T>(name, "path", ...)` declaration. |
| `RIV1020` | Error | The input type on a request with no JSON body (GET, DELETE, `.AcceptsBinary()`) is a dictionary, collection or scalar. Such an input must lower to route and query params, and this one has no properties to lower, so generation fails instead of emitting an operation without it. | Model the input as a record with one property per route or query param, or send the values as a JSON body with `Define.Post/Put/Patch`. |
| `RIV1021` | Error | An authored contract declares the same response status more than once, including a `.Returns(...)` collision with the success status. Such a contract fails at runtime and generation therefore aborts. | Declare a `[RivetUnion]` type if the status genuinely returns multiple shapes and return it once; otherwise remove the duplicate (often one `.Returns(...)` is mistyped). |
| `RIV1022` | Error | `[RivetRequestBody]` names a body type that is not represented independently by the endpoint input type, or one that carries files (an `IFormFile` or a list of them) while the input type carries none the form binders bind: a file nested in one of the input's members, or one without a public getter, doesn't make the body multipart. The input type alone makes a body multipart, as the runtime decides it, so the declared type can't add a file. | Declare the type of one of the input's non-route members, or a type whose every member the input declares under the same JSON name, type, and optionality, or remove the attribute. Put the file on the input type as one of its own members, with a public getter. |
| `RIV1023` | Error | Imported generated C# changed while raw schema provenance still targets its original typed shape. | Re-import the OpenAPI document, or remove/update the stale raw schema provenance before emitting. |
| `RIV1100` | Error | A parameter's binding source cannot be established from explicit declarations or the retained narrow conventions (exact route-token name match, `CancellationToken`, `IFormFile`) — the contract is refused rather than emitting an operation that silently omits the input. Also raised, instead of the operation vanishing, when a `[RivetEndpoint]` method or an abstract method on a `[RivetContract]` class has no HTTP verb, or when one of those or a `[RivetClient]` endpoint has no route template on the action or its class. (A `[RivetClient]` method with no verb is a helper and is left alone.) And when a form input's member is read under different names by the hosts that can serve it (a contract's `[FromForm(Name = ...)]` that the minimal-API form mapper ignores, or a `[DataMember(Name = ...)]` that MVC ignores), or from somewhere other than the form (a `[FromQuery]` or `[FromHeader]` on the member), so no one part name in the spec reaches every host. So is a form member only one host skips (for MVC a `[BindNever]` or `[BindingBehavior(BindingBehavior.Never)]` on the member or its class, or a class-level `[Bind("A", "B")]` include list that leaves it out, a positional record's constructor parameter included; for the form mapper `[IgnoreDataMember]`), a form input a host can't create (MVC needs a record's one exactly matching constructor or a public parameterless one, so it can't create an abstract class, a struct, or a record struct; the form mapper binds nothing on an abstract type or on one with more than one public constructor), and a file member nothing can set, which would make the body multipart for a part no binder reads. A get-only file collection (`List<IFormFile> Files { get; } = [];`) is a part on an MVC action, since MVC fills the list the getter returns, but only when its initializer creates a writable collection. One left null, computed on each read, or started as a read-only collection is a file nothing can set. On a contract even the live one is refused, because the form mapper can't set it. | Give the parameter an explicit binding (`[FromBody]`, `[FromQuery]`, `[FromRoute]`, `[FromHeader]`, `[FromForm]`, or `[FromServices]` for DI plumbing), or remove it from the action. For a missing verb or route, add the `[Http*]` attribute and a route template, or remove the method. For a form member, rename it for both binders with the same name (`[DataMember(Name = "x")]` and `[FromForm(Name = "x")]`, the latter on a positional record's parameter), or drop the rename or the binding attribute. Skip a member for both hosts or neither, make a form input a class with one public constructor (a parameterless one, or a positional record's), and give a file member, a contract's file collection included, a public setter or `init`. |
| `RIV1102` | Error | A response example or response content is authored on a body-forbidden status (1xx, 204, 205, 304) — HTTP forbids a message body on those statuses, so the authored content could never reach the wire. Reported at frontend parsing and again at emission as defense in depth; generation fails before any output is written. | Move the example/content to a status that allows a body, or remove it; the ordinary bodyless 204 response needs no example. |
| `RIV1103` | Error | A `[RivetScalar]` type is not a non-generic class/struct/record with one public readable `Value` property and a matching public constructor, without inheritance, competing converters or property-level JSON settings. | Give the type exactly one `Value` property (the Value type determines the scalar wire type), or remove `[RivetScalar]` if the type is an ordinary object. |
| `RIV1104` | Error | An endpoint mixes separate form fields or files with an explicit body parameter — a `[FromBody]` JSON body or a `[FromForm]` DTO whose recursive form shape Rivet cannot faithfully lower without emulating MVC's recursive form binder — the contract is refused instead of silently dropping the declared input. A contract that combines `.AcceptsBinary()` with `.AcceptsFile()` or `.FormEncoded()` is the same mix: a request body is raw bytes or a form, never both, and the runtime builder refuses it too. | Split the form DTO into scalar fields (each scalar emits a form part beside the file), move a `[FromBody]` body to a separate JSON endpoint, or accept the file-only surface. For a contract, keep one of `.AcceptsBinary()` and the form call. |
| `RIV1106` | Error | Two enum members produce the same wire value (via the declared converter's casing or duplicate `[JsonStringEnumMemberName]` pins) — generation fails instead of emitting an incorrect numeric schema. | Rename one of the colliding members (or fix its `[JsonStringEnumMemberName]`) so the wire values are distinct. |
| `RIV1107` | Error | An endpoint declares the same response status twice with different bodies — a `[ProducesResponseType]`/`.Returns(...)` declaration and a mapped `Results<>` branch disagree on the payload type, or one declares a body where the other declares none. One status carries exactly one shape; generation fails instead of silently letting the attribute win. | Align the attribute declaration and the `Results<>` branch (same payload type, or both bodyless), or drop the redundant declaration. |
| `RIV1108` | Error | Unsupported enum converter, wrong generic enum target, or string flags/aliases. | Use a built-in or Rivet enum converter with distinct values; use numeric serialization for flags. |
| `RIV1109` | Error | A contract endpoint declares the same response header more than once for one status. Header names are case-insensitive, so `.WithResponseHeader("ETag").WithResponseHeader("etag")` is a duplicate; generation fails instead of emitting both spellings. | Keep one `.WithResponseHeader(...)` per header name and status. |
| `RIV1110` | Error | A `[RivetEndpoint]` or `[RivetClient]` action binds a string-wire enum (a `Rivet*EnumConverter` or a `[JsonStringEnumMemberName]` rename) from route, query, header or form, directly or inside a complex parameter the host binds member by member, and the host would refuse a value the spec advertises. ASP.NET parses these itself and never asks the JSON converter: an MVC action needs each wire value to equal its member name ignoring case, a static `[RivetEndpoint]` (a minimal-API handler) needs it exactly. Which parameters count, host by host, is in [Limitations](/misc/limitations#enum-parameters-are-bound-by-asp-net). | Use a plain enum, the built-in `JsonStringEnumConverter<T>` without renames, or bind a `string` and parse it yourself. On MVC, camelCase and lowercase converters also bind, and an explicit `[ModelBinder]` exempts the parameter. |
| `RIV1111` | Error | A `[JsonConverter]` Rivet can't model sits on a walked type, property or field: anything but a supported converter on the enum type, `[RivetScalar]` or `[RivetUnion]`. The wire is whatever the converter writes, so the spec would describe the CLR shape instead. | On a primitive-typed property, pin the wire with `[RivetSchemaType("string")]` (or whichever JSON type the converter writes). Otherwise make the value a `[RivetScalar]` wrapper, or put a supported converter on the enum type itself. |
| `RIV1112` | Error | `[JsonNumberHandling]` with `WriteAsString` or `AllowNamedFloatingPointLiterals` reaches a number, or a collection of numbers, on a walked type, from the member or from the type being serialized. That includes `Int128`, `UInt128` and `Half`. A generic's `T` member is judged per instantiation: `Wrapper<int>` is refused, `Wrapper<string>` is fine. Strings go on the wire where the spec says number. `AllowReadingFromString` alone is accepted: numbers are still written as numbers, it only widens what the host reads. | Remove it, pin a primitive-typed property with `[RivetSchemaType("string")]`, or instantiate the generic with a non-number type argument. |
| `RIV1113` | Error | Rivet reads a contract endpoint from source and can't read this one: the field has no initializer, or its initializer isn't a `Define.*` builder chain (a helper call or another field, say); the endpoint is a property rather than a field; the chain calls something that isn't a Rivet builder method; an example has nothing in it; or a route is `null`; or a builder call is given a string, int or bool that isn't a compile-time constant. That last one covers every such argument, not just the route: `.Summary(text)`, `.Status(code)`, `.ProducesFile(type)`, `.QueryAuth(name)`, a scheme name, a scope. Rivet can't tell a variable from an omitted argument, so it used to skip the field or quietly fall back to the default. | Declare the endpoint as a `public static readonly` field initialised with `Define.*` and Rivet builder calls only, and pass every argument as a literal or a `const` (const strings can be concatenated or interpolated). |
| `RIV1114` | Error | A contract endpoint's security calls contradict each other: `.Anonymous()` (no security requirement at all) sits alongside `.Secure()` or `.OrAnonymous()`, or `.AndSecure()` has no `.Secure()` alternative to join (it comes first, or straight after `.OrAnonymous()`). The same goes for `[RivetSecure]`, `[RivetAndSecure]`, `[RivetOrAnonymous]`, and `[RivetAnonymous]` on a controller or action, where `[RivetAndSecure]` joins the `[RivetSecure]` written before it in source order, and so may not be split across partial declarations in different files. Rivet refuses rather than guessing which call you meant. | Use `.Anonymous()` (or `[RivetAnonymous]`) alone for an open endpoint, `.Secure(...)` plus `.OrAnonymous()` for optional credentials, and start every AND-group with `.Secure(...)`. Keep a level's security attributes in one file. |
| `RIV1115` | Error | MVC binding setup that can't be read statically, which decides what MVC binds, so `RIV1100`, `RIV1110`, `RIV4005` and `RIV4006` would be answering on a guess; generation and `--check` stop instead, naming the file and line. Three shapes: something in the app assigns `ApiBehaviorOptions.SuppressInferBindingSourcesForParameters` a value that isn't a compile-time constant (a config read, a variable, a compound assignment), read only when an annotated MVC action (generation) or a contract's MVC implementation (`--check`) is on an `[ApiController]` controller; a property filter (an `IPropertyFilterProvider`) other than `[Bind]`'s include list on an MVC parameter, the type it binds member by member, a nested member, or a contract's form input type, since MVC runs its code to pick the members it binds; and a `BindingBehaviorAttribute` subclass other than `[BindNever]` and `[BindRequired]`, whose behaviour its own constructor sets. A minimal-API-only check never reads the last two, since the form mapper ignores both. | Assign the constant `true` or `false` (a `const bool` works too). Name the members with `[Bind("A", "B")]`, or skip one with `[BindNever]` or `[BindingBehavior(BindingBehavior.Never)]`. |
| `RIV1116` | Error | A walked type has more than one `[JsonConstructor]` constructor. System.Text.Json refuses such a type at runtime, so there's no constructor whose parameters the spec could follow. | Keep `[JsonConstructor]` on one constructor. |
| `RIV1117` | Error | `[RivetSchemaType]` sits on a member whose type isn't a primitive or a nullable primitive. The attribute re-types a primitive leaf and nothing else, so on an object, a collection or a named type it would vanish without a trace, and the spec would go on describing the CLR shape you were trying to override. The message names the member. The same goes for `.WithResponseHeader<T>(schemaType: ...)` on a `T` that isn't a primitive. | When the type is a string (or another scalar) on the wire, say so on the type with `[RivetScalar]`. On a `[RivetScalar]` brand, which already is one, change the type of its `Value` property instead (a `[RivetFormat]` on the brand sets its format). Otherwise remove the attribute. For a response header, drop `schemaType:`. |
| `RIV1118` | Error | A `[JsonExtensionData]` member System.Text.Json won't accept: anything but a `JsonObject` or a type implementing `IDictionary<string, JsonElement>` or `IDictionary<string, object>` (`Dictionary`, `SortedDictionary`, `ConcurrentDictionary` and friends), or a second bag on the type or anywhere down its base chain. Also raised when the bag sits on a type marked `[JsonUnmappedMemberHandling(JsonUnmappedMemberHandling.Disallow)]`: one says "keep the unknown members", the other "refuse them", and STJ throws at runtime rather than pick. | Type the bag as one STJ accepts, keep one bag, or drop either the bag or the `Disallow`. |
| `RIV1119` | Error | A member is `[JsonRequired]` (or C# `required`) and may also be left out when written: it's `[RivetOptional]`, or `[JsonIgnore(Condition = WhenWritingNull)]`/`WhenWritingDefault`. Reading demands the member while writing may omit it, and one schema can't say both, so generation stops and names the member. | Drop the requirement if the member really is optional, or drop the attribute that lets it be omitted. |
| `RIV1120` | Error | A response status OpenAPI can't key a response by: a string key that isn't a status code, a `1XX`-`5XX` range, or `default` (in any casing, which is emitted as `default`), or an `int` status outside 100 to 599. Left alone it would reach the spec as written, where no client can match it, and the runtime refuses the same keys at startup, on every status-taking call. | Use a status code (`"404"` or `404`), a range (`"4XX"`), or `"default"` in `.StatusKey(...)`, `.Returns(...)`, `.ResponseContent(...)`, and the other status-taking calls, or a code from 100 to 599 in `[ProducesResponseType]`. |
| `RIV1121` | Error | An `[assembly: RivetSecurityScheme(...)]` or `[assembly: RivetOAuthFlow(...)]` describes a scheme that can't exist. That's the same scheme name declared twice; a type other than `apiKey`, `http`, `oauth2`, `openIdConnect`, or `mutualTLS`; an apiKey location other than `query`, `header`, or `cookie`; an OAuth2 flow other than `implicit`, `password`, `clientCredentials`, or `authorizationCode`; a scheme missing its type or the field its type needs (an apiKey's name and location, an HTTP scheme, an OpenID Connect URL); a flow whose scope names and descriptions don't pair up; a flow or scope declared twice; or a null scope. A `[RivetOAuthFlow]` whose scheme isn't a declared `oauth2` one is an error too, as is a `[RivetGlobalSecurityScheme]` whose order no `[RivetGlobalSecurity]` starts. So is any `[RivetSecurityScheme]`, `[RivetOAuthFlow]`, `[RivetGlobalSecurity]`, or `[RivetGlobalSecurityScheme]` whose arguments Rivet can't read at all (a null name, flow, or scope list, or arguments from another `Rivet.Attributes` version). Each of these used to drop out of the spec without a word, or crash. Generation stops rather than guess what the scheme was meant to be. | Fix the attribute's arguments: declare each scheme, flow, and scope once, give each flow an `oauth2` scheme, and start every alternative you add a scheme to with `[RivetGlobalSecurity]`. Use the same version of `Rivet.Attributes` and the tool. [Attributes: Security](/reference/attributes#security) has the shapes. |
| `RIV1122` | Error | Generated metadata Rivet reads back is malformed, which almost always means generated code that went stale or got hand-edited. Today that's a `[RivetGeneratedType]` whose `DiscriminatorSchemaJson` isn't valid JSON or a JSON object, whose `enum`, `const` or `type` can't carry the tag the variant is registered with, or that sits on a type no base registers with `[JsonDerivedType]`, where there's no tag property for it to describe at all. Emitting any of those would publish a spec that refuses, or never mentions, the very tag System.Text.Json writes, so generation stops and names the type. Or it's a `[RivetGeneratedSchema]` enum entry (`isEnum`) whose name no enum in the compilation has, so its metadata has no enum schema to join. The same ID covers every other attribute import writes and generation reads back: a `[RivetGeneratedSchema]` or `[RivetGeneratedSchemaMetadata]` with missing or mistyped arguments, unparseable metadata JSON, a name another generated schema already has, or a `$ref` to a generated schema that doesn't exist; an OpenAPI provenance attribute (`[RivetDocumentInfo]` twice, a `[RivetPreservedField]` naming something other than an `x-` extension or a documentation field, a `[RivetOperationProvenance]` schema that isn't a JSON object, and the rest of the family) that doesn't read, or one with a different number of arguments than the tool reads, which means the project's `Rivet.Attributes` and the rivet tool are different versions; and a synthetic type that references itself, which can't be inlined. | Re-import the OpenAPI document. If you edited the JSON on purpose, make it a schema object that admits the tag: `{"type":"string"}`, or an `enum` that lists it. If the type isn't a registered variant, remove `DiscriminatorSchemaJson`. A stray enum entry: re-import, or delete the attribute. An argument-count mismatch: use the same version of `Rivet.Attributes` and the tool, then re-import. |
| `RIV1123` | Error | An authored value isn't the shape its slot needs. A builder argument's JSON (`metadataJson`, `exampleJson`, `examplesJson`, `schemaExamplesJson`, `referencedComponentsJson` and the like, as import writes them), a `[RivetDefault]` or `[RivetExample]` value, or a JSON value in schema metadata doesn't parse, or isn't the kind its keyword takes: `examples` on a schema is an array, `examples` on a parameter or header is an object of Example Objects. Or `.Parameter<T>(name, location, ...)` names a location other than `path`, `query`, `header`, or `cookie`, or a `path` parameter whose name matches its route token only ignoring case (an OpenAPI path parameter is matched to its token by its exact name). Written as-is, any of these would make an invalid spec, so generation stops and names the argument. | Fix the value: valid JSON of the kind the message names (a JSON string keeps its quotes), or one of the four locations, or the token's exact spelling. If import wrote it, re-import. |
| `RIV1124` | Error | An Azure Functions project's `host.json` can't be read, isn't JSON, or gives `extensions.http.routePrefix` as something other than a string. `--check` needs the prefix to compare a function's route with its contract's, and assuming the default `api` would compare against a prefix the host doesn't use. | Fix `host.json` so the prefix is a string (`""` for none), or set `AzureFunctionsJobHost__extensions__http__routePrefix`, which wins over the file. |
| `RIV1125` | Error | A route constraint can't hold with what declares its token (the input property, a `.Parameter<T>(name, "path", ...)`, or a `[RivetEndpoint]` action parameter). That covers: a type constraint that disagrees with the type (`{id:int}` over a `string Id`); a keyword the type can't carry (`min`/`max`/`range` on a non-integer, `length`/`minlength`/`maxlength`/`alpha`/`regex` on a non-string); two type constraints; two patterns (with `[RegularExpression]` or each other); bounds that, intersected with the member's own, admit no value; a malformed constraint argument (a `regex` with no pattern among them); and a template routing refuses at startup (`{a}{b}`, `{id?=5}`, an unclosed `{`, and, on a controller action, a `[RivetEndpoint]` method, or an abstract contract's method, a parameter name used twice; a static contract's field, the shape import writes, still reads a repeat, as an imported path can carry one, until import's handling of it is decided). So is a literal brace in the path (<span v-pre>`/a/{{x}}`</span>, which routing serves as `/a/{x}`): OpenAPI path templating has no escape for a brace, so the spec can't hold the path. Routing then admits one thing and the handler binds another, and the spec can only describe one of them. Also raised for an attribute route MVC refuses at startup: a `[token]` nothing supplies a value for (`[area]` with no `[Area]`, or a typo), an unclosed `[`, or two route value attributes keying one value on the same action or controller; and for a token only a route value attribute Rivet can't follow to constant arguments could supply. | Make the constraint and the property agree: change the property's type, or the constraint (or drop it and let the property type the parameter), or drop one of the two patterns. A template routing or MVC refuses needs fixing whatever declares its tokens, a route value attribute Rivet can't read needs constant constructor arguments (or the segment written into the template), and a literal brace has to come out of the path. |
| `RIV1126` | Error | The C# can't be read, so there's nothing to generate, check, or list routes from. No MSBuild instance can be found to load the `--project` (Rivet looks for the .NET SDK under `DOTNET_ROOT` and the usual install folders), MSBuild can't open the `--project` file as a C# project (a `.sln`, an `.fsproj`, or a stray file), the project yields no compilation, or the project or source files don't compile. `RIV1024`-`RIV1099` were once reserved for the dropped `rivet/php` runtime. Nothing
registers them, and nothing ever will.

  `x-rivet-csharp-type: TimeSpan`, so the diagnostic no longer exists.
- ~~`RIV1011`~~ (`UnsupportedChar`) — retired in P2 wave 6. `char` used to emit an
  untyped (empty) schema with this warning; it now maps to a length-1 `string` schema
  (`minLength`/`maxLength: 1` — the System.Text.Json wire shape) with
  `x-rivet-csharp-type: char`, so the diagnostic no longer exists.
- ~~`RIV1012`~~ (`UnsupportedObject`) — retired in P2 wave 6. `object` used to emit an
  untyped (empty) schema with this warning; the untyped schema *is* the honest spec for
  "any JSON value", so `object`/`object?` now map to it deliberately and silently, and
  the diagnostic no longer exists.
- ~~`RIV1101`~~ (`JsonIncludeFieldNotRepresented`) — retired in 0.49.0. It was registered
  in 0.42.0 as a reserved slot for `[JsonInclude]` shapes the walker couldn't prove
  statically, but every shape it could meet (mixed accessors, private accessors,
  included fields) was already worked out, so nothing ever emitted it. A diagnostic
  that can't fire is a promise nobody checks, so it went.
- ~~`RIV1105`~~ (`RivetEnumNamingPolicyWithoutStringConverter`) — retired in the
  converter-family wave (0.44.0). The casing convention now lives in the enum's
  `[JsonConverter]` declaration itself (`RivetCamelCaseEnumConverter<T>` family), so a
  policy cannot exist without a string wire and the dangling-marker case is unexpressible.
- ~~`RIV2004`~~ (`MultipartInputTypeMissing`) — retired in 0.50.0. A `--from` multipart
  endpoint whose `inputTypeName` had no definition in `types` got this warning, telling
  the producer to ship one. rivet-ts never does, on purpose: it lowers the input into
  params, and the emitter builds the body inline from them. So `inputTypeName` is a name
  hint for that inline body, the warning fired on every such contract with nothing to fix,
  and it went.
- ~~`RIV3002`~~ (`ImportSecuritySchemesDropped`) — retired in 0.49.0. It promised
  that only the first security scheme survived import; nothing has emitted it since
  0.41.0, when the importer started keeping every alternative, AND-group and scope. Those
  now land in generated C# as `.Secure(...)`, `.AndSecure(...)` and `.OrAnonymous()`, so
  the warning had nothing left to warn about.
- ~~`RIV3004`~~ (`ImportAdditionalPropertiesDropped`) — retired in 0.42.0. A named object
  declaring both `properties` and `additionalProperties` used to lose its extension data
  with this warning; it now keeps typed properties plus extension data, so nothing is
  dropped.
- ~~`RIV3007`~~ (`ImportAliasRefCycle`) — retired in 0.45.0. Nothing ever emitted it: alias
  `$ref` cycles are broken before mapping and reported as `RIV3001`.
- ~~`RIV3012`~~ (`ImportEnumConstraintDropped`) — retired in 0.49.0. An enum that couldn't
  become a C# enum (one value, booleans, numbers, `[null]`, mixed or out-of-range values)
  used to lose its values with this warning, and an untyped one became a `string`. Every literal enum now keeps them: the C# type comes
  from the values (`{ enum: [true] }` is a `bool`), and the values travel in the generated
  metadata, so the spec re-emits them.
- ~~`RIV3013`~~ (`ImportDeclaredPropertiesDropped`) — retired in 0.42.0. An inline object
  declaring both `properties` and `additionalProperties` used to lose its typed properties
  with this warning; it now keeps both, so nothing is dropped.
