# FABLE_TEST_FIXES.md — test-suite audit & conversion worklist

Audited 2026-06-10, covering `Rivet.Tests/` in this repo and `rivet-ts/tests/`. Companion to `FABLE_REVIEW.md` (both repos) and `FABLE_REWRITE.md` — finding IDs (A1, E4, I3, N1, S3, X14, …) refer to those documents.

**The problem this addresses:** the suites were largely LLM-written and contain *bug-pinning tests* — assertions that enshrine silent-skips and known-wrong behavior as golden. When a bug gets fixed (a loud diagnostic added, a default corrected), these tests go red and *defend the bug*. This document classifies every test so fixes don't get reverted by their own regression suite.

**Populations:**
- **P1 (keep)** — pins desired behavior with a real oracle.
- **P1† (port oracle)** — desired *analysis-side* behavior asserted through `ClientEmitter`/`TypeEmitter` string output; the behavior survives the pivot, the oracle dies in Phase 3. Migrate assertions to walker-IR/`TsEndpointDefinition`/OpenAPI before deletion or these break en masse.
- **P2 (convert)** — pins a known bug or silent-skip as golden. Each entry says what the converted test must assert.
- **P3 (dies with deleted code)** — exclusively covers `ClientEmitter`/`TypeEmitter`/Zod/`rivet.ts` (or, in rivet-ts, the bespoke wire format). Zero further investment; delete at Phase 3/5.
- **P0 (theatre)** — asserts nothing meaningful: tautologies, string-greps standing in for compilation, names claiming behavior the body doesn't test.

**The conversion rule** (apply everywhere): *every absence assertion must be paired with a diagnostic assertion* — code, message, and file/line location. If production can't satisfy it yet, the test goes red and becomes the bug's executable spec.

# Part 0 — Systemic findings (act on these first)

- **SYS-1 — The .NET suite pins OpenAPI 3.0.3; the pivot targets 3.1.** Dozens of tests assert `"3.0.3"` and 3.0-style `nullable: true`/`allOf`-wrap (e.g. `OpenApiEmitterTests.cs:77, 1323`; `FromContractTests.cs:78`). One test **explicitly forbids 3.1 patterns**: `Emitted_Json_Contains_No_OpenApi31_Nullable_Patterns` (`OpenApiEmitterTests.cs:1298-1347`, `Assert.DoesNotContain("\"null\"", json)`). P1 today; scheduled mass-conversion when the emitter goes 3.1 — the forbid-3.1 test specifically becomes P2 (convert to: emits valid 3.1 `type: ["string","null"]`, spectral-validated).
- **SYS-2 — No conformance-gate oracle exists anywhere.** Nothing runs spectral/redocly; nothing runs `openapi-typescript` + `tsc` over emitted specs. Seeds to generalize: `Emitted_OpenApi_Is_Valid_Spec` (`OpenApiEmitterTests.cs:1813` — the suite's only third-party validator), `All_Refs_Resolve_To_Existing_Schemas` (`:1759`), the hand-rolled `Valid_OpenApi_Structure` (`:1633`, subsumed by spectral later), the entire `OpenApiRoundTripTests.cs` self-loop suite (conformance check #3 in embryo), the `TypeScriptCompilationTests.cs` tsc harness (fixtures die, **harness is check #2**), and rivet-ts's `tscValidate` (`rivet-type-to-typescript.lifecycle.test.ts:40-62`).
- **SYS-3 — Round-trip compile helpers mask I3.** `RealWorldImportTests.GetCompilationErrors`/`DeduplicateFiles` (`RealWorldImportTests.cs:33-47, 175-181`) dedupe importer output **by filename, keeping the first** — the I3 failure shape built into the oracle. The compile gate passes even when production output is corrupted. Convert: fail on duplicate filenames with non-identical content.
- **SYS-4 — ~500+ exact-substring assertions on generated C#** across importer tests. Real oracles (most are backed by a compile check) — keep, but expect a mass-edit on any cosmetic `CSharpWriter` change.
- **SYS-5 (rivet-ts) — All six golden fixtures bake in N1** (`"optional"` on endpoint params; 2–11 occurrences each), and **three bake in X14** (empty `responses: []` for void endpoints: expressive `ping` GET, members `health` GET, multipart `uploadDocument` PUT — so X14 is broader than GET). Every `toEqual(golden)` therefore defends N1/X14.
- **SYS-6 (rivet-ts) — `UPDATE_GOLDEN=1` self-rewrite machinery** (`lower-contract-bundle.lifecycle.test.ts:125-131, 766-772`; `expressive-contract.lifecycle.test.ts:47-51`) is a bug-laundering device: any behavior change, right or wrong, can silently re-pin the goldens. Delete it or gate it behind review when goldens are converted.
- **SYS-7 (rivet-ts) — Dead infrastructure:** orphaned fixture dirs `handler-entrypoint/`, `handler-entrypoint-extraction-error/`, `handler-entrypoint-node-import/` (referenced by zero tests/src; only a tsconfig exclude). Empty `tests/setup.ts` wired in `vitest.config.ts:8`. `test:watch` runs bare `vitest` while fixtures import from `dist/` — watch mode tests stale output.
